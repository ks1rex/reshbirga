# Гайд администратора Ebu.Gubkin

Документ описывает **только то, что реально работает в коде** на 2026-07-26.
Всё, что задумано, но не доделано, собрано в последнем разделе «В планах и известные ограничения».
Если в тексте написано «не работает» или «показывает неправильно» — это проверено по коду, а не предположение.

Тот же текст доступен внутри сайта: **Админка → Справка** (адрес `/admin/help`).

## Доступ в админку

Админка живёт по адресу `/admin`.

Что нужно, чтобы туда попасть:

1. Быть зарегистрированным и войти на сайт.
2. Иметь в своём профиле отметку «администратор».

Отметка администратора не выдаётся через интерфейс сайта — самый первый администратор
проставляется вручную в базе данных. Дальше он может выдавать и снимать права другим
людям в разделе «Пользователи».

Как понять, что права есть: в верхней панели сайта рядом с балансом появляется
иконка щита — это ссылка на админку. У обычного пользователя её нет.

Если зайти на `/admin` без прав, сайт молча перебросит на главную страницу —
никакого сообщения «доступ запрещён» не будет.

Меню админки: на компьютере — колонка слева (её можно свернуть в узкую полоску
кнопкой сверху), на телефоне — сетка плиток над содержимым страницы.

## Разделы админки

Всего 15 рабочих разделов плюс эта Справка. Ниже — по каждому.

### Дашборд

Первая страница админки. Семь плиток с цифрами:

| Плитка | Что показывает |
|---|---|
| Пользователи | Всего аккаунтов, ниже — сколько из них заблокировано |
| Активных заказов | Сумма заказов в статусах «открыт», «в работе», «ожидает подтверждения» и «спор» |
| Открытых споров | Сколько споров ждут решения |
| Тикетов поддержки | Сколько обращений открыто или ждут ответа пользователя |
| Заявок на пополнение | Сколько заявок ждут подтверждения |
| Заявок на вывод | Сколько заявок ждут выплаты |
| Комиссия собрана | Вся комиссия, удержанная при выводах |

Ниже — блок «Заказы по статусам»: сколько заказов в каждом статусе. Названия статусов
там выводятся английскими, как они хранятся в базе, — это не ошибка, просто не переведено.

На что обратить внимание:

- Плитка «Активных заказов» ведёт не на заказы, а на список пользователей — ошибка ссылки.
  Чтобы посмотреть заказы, идите в раздел «Заказы».
- Плитка «Тикетов поддержки» вообще не кликается, хотя раздел «Поддержка» есть.
- Если вместо цифры заявок стоит прочерк — данные не загрузились, обновите страницу.
- Статистика по заказам считается по последним 2000 заказам. Пока платформа маленькая,
  это неважно, но при росте цифры станут неполными.

### Финансы

Три карточки.

**Прибыль платформы** — построчно:

| Строка | Что это |
|---|---|
| Комиссия с вывода средств | Основной доход. Всё, что платформа удержала при подтверждённых выводах |
| Комиссия реферальных пополнений | Всегда ноль, см. предупреждение ниже |
| Выплачено рефереру | Сколько всего выплачено реферальных бонусов, вычитается из прибыли |
| Выручка ГОСТ-токенов | Деньги, полученные за токены ГОСТ-калькулятора |
| ИТОГО | Сумма всего вышеперечисленного |

Важно про строку «Комиссия реферальных пополнений»: рядом с ней в интерфейсе нарисован
значок «5%», но эта строка на практике **всегда показывает ноль**. Раньше платформа брала
комиссию при пополнении, теперь — только при выводе, поэтому с пополнений (в том числе
реферальных) больше ничего не удерживается. Значок «5%» — просто подпись, оставшаяся
от старой схемы, и он не читается из настроек: если вы поменяете процент реферального
бонуса, надпись всё равно останется «5%».

**Деньги пользователей** — суммарный баланс всех кошельков. Это не ваши деньги: их нужно
всегда держать доступными, потому что люди в любой момент могут запросить вывод.

**Расходы / Итог** — поле «Расходы платформы», которое вы заполняете руками (кнопка
«Изменить»): серверы, реклама, что угодно. Ниже — «Доступно к выводу» = прибыль минус
расходы. Это просто ваша заметка для себя, ни на какие расчёты в системе она не влияет.

### Пополнения

Список заявок на пополнение кошелька. По умолчанию видны только ожидающие,
кнопка «Показать все» открывает историю.

По каждой заявке: кто подал, заявленная сумма (сколько человек говорит, что перевёл),
поле «Подтверждённая сумма» (сколько вы реально получили — можно исправить),
метка «РЕФ.», дата, статус.

**Кнопка «Подтвердить»** одной неделимой операцией:

- зачисляет подтверждённую сумму на баланс пользователя один к одному, без вычетов;
- увеличивает его накопленную сумму пополнений (после 5000 ₽ выдаётся достижение);
- если положен реферальный бонус — начисляет его пригласившему и записывает обе операции в журнал;
- отправляет уведомление в Telegram.

Неделимость важна: раньше бывало «заявка отмечена подтверждённой, а деньги не зачислены».
Сейчас либо проходит всё, либо не проходит ничего. Повторное нажатие вернёт
«Заявка уже обработана» — двойного зачисления не будет.

**Кнопка «Отклонить»** только меняет статус. Деньги не зачисляются, ничего возвращать не нужно.

На что обратить внимание:

- **Никогда не подтверждайте пополнение, пока реально не увидели деньги.** Подтверждение
  необратимо: кнопки «отменить зачисление» нет, придётся править баланс в базе руками.
- Поля для комментария при отклонении в админке нет, хотя пользователю такой комментарий
  показывается в его кошельке. То есть отклонить можно, а объяснить причину через админку — нет.
  Объясняйте через раздел «Поддержка».
- Метка «РЕФ.» рисуется, если у человека есть пригласивший и у того меньше трёх зачтённых
  пополнений. Число «три» зашито в интерфейс жёстко, а настоящий предел берётся из настроек.
  Если вы измените «Макс. реф. бонусов» в Настройках, метка начнёт врать (сам расчёт бонуса
  при этом останется правильным).
- Пользователь может создать не больше 3 заявок в час и не больше 500 000 ₽ за заявку.

### Выводы

Список заявок на вывод. По умолчанию — ожидающие.

По каждой заявке: пользователь, сумма, **«К выплате»** (сумма минус комиссия — именно
столько нужно перевести человеку), номер карты, дата, статус.

Как это работает по деньгам: при создании заявки вся сумма уже списана с баланса
пользователя и удерживается. Комиссия удерживается здесь, при выводе.

**Кнопка «Выплачено»** ничего никуда не переводит. Она только:

- меняет статус заявки на «выплачено»;
- записывает удержанную комиссию в раздел «Финансы».

Реальный перевод денег на карту вы делаете сами, вручную, через банк.

**Порядок действий строго такой:**

1. Смотрите сумму в колонке «К выплате».
2. Переводите эту сумму на указанную карту через банк.
3. Убеждаетесь, что перевод прошёл.
4. Только теперь нажимаете «Выплачено».

Если нажать раньше и перевод не пройдёт — система будет считать, что человеку заплатили,
а он останется без денег и без заявки. Автоматического отката нет.

**Кнопка «Отклонить»** возвращает пользователю **полную** сумму на баланс (без вычета
комиссии) — это делается автоматически, ничего доделывать не нужно.

Если в колонке «К выплате» стоит прочерк — не загрузился процент комиссии.
Не выплачивайте наугад, обновите страницу.

### Споры

Список открытых споров. По каждому: причина спора, поле для комментария администратора,
две галочки («Забанить заказчика», «Забанить исполнителя») и две кнопки решения.

**«Вернуть заказчику»**: заказ отменяется, заказчику возвращается вся зарезервированная
сумма, включая залог, если он был.

**«Выплатить исполнителю»**: заказ завершается, исполнитель получает стоимость работы,
и **залог тоже уходит исполнителю** (считается конфискованным в его пользу). Это важно
учитывать: решение в пользу исполнителя дороже для заказчика, чем просто оплата работы.

В оба случая уходит уведомление в Telegram.

**Спор разрешается только один раз.** Система атомарно «забирает» спор при первом нажатии;
повторное нажатие или второй администратор получит ошибку «Спор уже разрешён».
Двойная выплата невозможна — это защита на уровне базы, а не на уровне кнопки.

Галочки бана срабатывают вместе с решением: человек блокируется, но уже начатые
у него другие сделки не прерываются.

**Известная поломка этой страницы.** Интерфейс ждёт от сервера название заказа и ники
участников, а сервер присылает их в другом виде и вообще не присылает ссылку на заказ.
Из-за этого при появлении хотя бы одного открытого спора страница «Споры», скорее всего,
откроется пустой (белый экран), и разрешить спор через админку не получится.
Пока это не исправлено:

- о новом споре вы узнаёте из Telegram-уведомления;
- сам заказ ищется в разделе «Заказы» по статусу «Спор»;
- переписку можно прочитать в разделе «Чаты»;
- а вот кнопки решения доступны только на этой странице — то есть до починки
  споры фактически не закрываются. Это первое, что стоит отдать разработчику.

### Форум

Модерация форума. Две вкладки.

**AI-флаги** — посты, которые автоматическая проверка сочла подозрительными.
Видны автор, текст, причина. Кнопки: «Одобрить», «Удалить», «Забанить автора».

Как работает автопроверка:

1. В момент отправки поста срабатывает мгновенный фильтр по словам — экстремизм,
   явная реклама, спам (три одинаковых сообщения за 10 минут). Такой пост
   **не публикуется вообще** и в админку не попадает.
2. Всё остальное публикуется сразу, а через минуту-десять фоновая проверка
   отдаёт текст на разбор ИИ. Если ИИ помечает пост — он попадает во вкладку
   «AI-флаги», и в Telegram уходит уведомление.

**Помеченный пост остаётся видимым на форуме**, пока вы его не удалите. Флаг ничего
не скрывает, это только сигнал вам.

«Удалить» — мягкое удаление: пост остаётся в базе, но обычные пользователи видят
пустое место, а администратор — исходный текст. Восстановить пост через админку нельзя.

Если на сервере не настроен ключ ИИ-сервиса, второй уровень проверки просто не работает:
все посты сразу считаются одобренными, и вкладка «AI-флаги» всегда пустая. Это не поломка,
а отсутствие настройки.

**Жалобы** — жалобы пользователей на посты. Видно, кто жалуется, причина, текст поста
и его автор. Кнопки: «Оставить» (жалоба закрывается, пост остаётся) и «Удалить пост».

Категории форума настраиваются **не здесь**, а в разделе «Настройки».

### ГОСТ-шаблоны

Редактор шаблонов расчётов для ГОСТ-калькулятора. Слева список шаблонов, у каждого точка:
зелёная — шаблон был изменён вами, серая — используется оригинал с сервера.

Справа пять вкладок:

| Вкладка | Что можно править |
|---|---|
| Основное | Название, дисциплина, тип работы, тексты введения и заключения, инструкции к заключению |
| Исходные данные | Обозначение, значение, единица измерения, описание — по каждому уже существующему параметру |
| Таблицы | Название, подписи осей, тип интерполяции, списки значений по X и по Y |
| Разделы | Название и уровень раздела, вводный текст, а внутри — шаги расчёта: обозначение результата, единица, описание, формула. Шаги можно переставлять стрелками |
| Литература | Список источников — единственное место, где можно **добавлять и удалять** пункты |

Ограничение: добавить новый шаг, новый раздел, новую таблицу или новый исходный параметр
через админку **нельзя** — только править и переставлять то, что уже есть. Новые сущности
добавляются разработчиком в файлах шаблона.

Перед сохранением проверяется: название не пустое, у каждого шага заполнены формула
и обозначение результата, в таблицах одинаковое количество значений по X и по Y.
Ошибочные поля подсвечиваются красным.

«Сохранить изменения» не меняет файлы на сервере — создаётся ваша версия шаблона в базе,
и она используется вместо файла. «Сбросить к оригиналу» удаляет вашу версию и возвращает
исходный файл. Кнопка сброса появляется только если ваша версия существует.

Если попытаться переключиться на другой шаблон с несохранёнными правками, появится
предупреждение. Закрытие страницы с несохранёнными правками тоже спросит подтверждение.

Если на сайте не настроен адрес ГОСТ-сервиса, страница напишет об этом и ничего не покажет.

Отдельно: **сам ГОСТ-калькулятор сейчас закрыт для всех, кроме администраторов.**
Обычный пользователь, зайдя в раздел ГОСТ, видит надпись «В разработке»; при клике
по притемнённой плитке в меню — всплывающее окно с тем же текстом. Администратор
пользуется калькулятором как обычно.

### Прогрев расписания

Зачем это нужно. Сайт расписания университета отдаёт данные только после ввода капчи,
поэтому платформа не запрашивает расписание «на живую». Вместо этого администратор
один раз проходит капчу, а сервер выкачивает расписание всех групп в свой кеш,
и уже из кеша его читают пользователи в разделе «Расписание».

Страница показывает текущее состояние — простой, выполняется, нужна капча, готово, ошибка —
и одну-две кнопки под него.

Как прогреть:

1. Нажать «Начать прогрев».
2. Дождаться картинки капчи и ввести код.
3. Ждать. Прогресс-бар показывает, сколько групп и недель уже загружено.

Сколько ждать: качаются все московские факультеты, все их группы и по три недели
расписания на каждую, с паузой между запросами. Это десятки минут. Страницу можно
закрыть — процесс идёт на сервере, состояние подхватится при следующем открытии.
Кнопка «Отменить» останавливает процесс.

**Кеш живёт 30 часов.** Это значит, что прогрев нужно запускать примерно раз в сутки,
иначе у пользователей раздел «Расписание» перестанет работать и будет писать, что
администратор должен запустить прогрев. Автоматического расписания прогрева нет —
это ручная ежедневная обязанность.

На что обратить внимание:

- Если сессия истекает посередине, система снова попросит капчу. После её ввода
  прогрев начинается **с самого начала**, а не с того места, где остановился.
- Если сервер перезапустится во время прогрева, состояние в базе может застрять
  на «выполняется». В этом случае «Начать прогрев» будет отвечать «Уже выполняется»,
  а «Отменить» не поможет — отмена работает только для процесса, который ещё жив.
  Выйти из этого состояния из админки нельзя, нужна помощь разработчика.

### Заказы

Полный список всех заказов платформы: название, заказчик, исполнитель, сумма, статус, дата.
Фильтр по статусу, поиск по названию заказа и по нику участника, страницы по 50 записей.

Статусы: «Открыт», «Ожидает оплаты», «В работе», «Нужна доплата», «Ожидает подтверждения»,
«Завершён», «Спор», «Отменён».

Раздел **только для просмотра** — изменить заказ, отменить его или вмешаться в сделку
из админки нельзя. Единственный способ повлиять на деньги по заказу — разрешить спор.

### Чаты

Все переписки платформы: и чаты по заказам, и обращения в поддержку. Фильтр по типу,
поиск, страницы по 50.

Открыв переписку, администратор видит всю историю целиком и **может писать в неё
от имени администрации** — сообщение будет помечено как административное.

**Известная проблема отображения.** Сервер отдаёт названия и участников в одном виде,
а этот список ждёт их в другом. В результате почти все строки выглядят как
«Без названия» и «Участники не найдены», а автор последнего сообщения подписан
«Система». Сама переписка при открытии показывается правильно. Поиск на сервере
работает (по нику, по названию заказа, по теме тикета) — просто в списке результат
плохо подписан. Для обращений в поддержку пользуйтесь разделом «Поддержка»:
там то же самое отображается корректно.

### Модерация

Модерация личных сообщений. Сюда попадают сообщения, в которых:

- найдены контактные данные — метка «Regex-флаг»;
- ИИ заподозрил нарушение — метка «AI-флаг».

По умолчанию видны только непроверенные, кнопка «Показать все» открывает остальные.

Важно понимать, что происходит с такими сообщениями: **ничего.** Они доставляются
собеседнику и остаются видны. Пометка — только для вас. Отправитель при этом видит
предупреждение, что сообщение похоже на обмен контактами.

Исключение: если в заказе явно включён обмен контактами, сообщение с контактами
не считается нарушением.

Кнопка «Проверено» тоже ничего не делает с сообщением — она только убирает его
из списка непроверенных. Наказать автора можно только вручную, через раздел
«Пользователи» (бан).

ИИ-проверка переписки запускается не сразу, а после завершения или отмены заказа —
то есть флаги по сделке появляются, когда она уже закончилась.

### Поддержка

Список обращений пользователей. Статусы: «Открыт», «Ответили», «Закрыт».

Открыв обращение, вы читаете переписку и отвечаете в неё. Ваш ответ автоматически
переводит тикет в статус «Ответили».

Кнопка «Закрыть тикет» закрывает обращение — переписка становится только для чтения.

Обратно открыть тикет из админки нельзя. Но если пользователь напишет в закрытый
тикет ещё раз, он автоматически откроется снова, и обращение вернётся в список.

### Журнал

Журнал транзакций — только чтение, без возможности что-то изменить.
Фильтры: тип операции, никнейм, диапазон дат.

На что обратить внимание:

- Показывается максимум 500 последних записей. Надпись «Показано: N / макс. 500» —
  об этом же.
- Фильтр по никнейму применяется **после** выборки этих 500 записей. Поэтому по
  человеку, который давно ничего не делал, журнал покажет «нет записей», хотя
  операции у него были. Сузьте диапазон дат — тогда в 500 записей попадёт нужный период.
- В списке типов нет покупок VIP, покупок ГОСТ-токенов и реферальных пополнений —
  отфильтровать по ним нельзя, и в таблице они выводятся английским названием типа.
- Реферальное пополнение из-за этого показывается со знаком минус, хотя это приход.
  Не пугайтесь: сами деньги начислены правильно, ошибка только в раскраске строки.

### Пользователи

Все аккаунты: ник, email, баланс, дата регистрации, метки ADMIN и БАН.
Поиск по нику и email, фильтры «Все» / «Заблокированные» / «Администраторы».

Два действия:

- **Заблокировать / Разблокировать.** Заблокированный не может создавать заказы,
  услуги, отклики и посты на форуме, не может писать в чат по заказу. Писать в поддержку
  он по-прежнему может — это сделано специально, чтобы человек мог оспорить блокировку.
  Уже начатые сделки бан не прерывает.
- **Сделать администратором / Снять админа.** Снять права у последнего администратора
  система не даст — вернёт ошибку.

На что обратить внимание:

- Список загружается целиком, без страниц. Поиск и фильтры работают в браузере
  по уже загруженным данным. Пока аккаунтов немного — нормально, дальше страница
  начнёт тормозить.
- Аватарки в этом списке не отображаются никогда — сервер их не присылает, показываются
  кружки с первой буквой ника. Это не сломанные картинки.
- **VIP-статус в этом разделе не виден вообще.** Узнать, есть ли у человека VIP,
  из админки нельзя.
- Рейтинги и количество отзывов сервер присылает, но в таблице они не выводятся.
  Смотрите публичный профиль пользователя.

### Настройки

Три секции.

**Реквизиты оплаты** — большое текстовое поле. Это ровно тот текст, который пользователь
увидит на странице пополнения кошелька: номер карты, телефон для перевода, инструкции.
Сохраняется своей кнопкой.

**Параметры платформы** — каждое поле сохраняется **отдельной** кнопкой рядом с ним.
Забыли нажать — значение не сохранилось.

| Группа | Настройка | Что меняет |
|---|---|---|
| Общее | Цена ГОСТ-токена | Сколько рублей стоит один токен |
| Общее | Реферальный бонус, % | Процент, который получает пригласивший с пополнения приглашённого |
| Общее | Макс. реф. бонусов | Сколько первых пополнений приглашённого приносят бонус |
| Общее | Мин. сумма для реф. бонуса | Пополнение меньше этой суммы бонус не приносит |
| Вывод средств | Комиссия с вывода, % | Сколько платформа удерживает при выводе |
| VIP | Цена VIP на месяц / на год | Базовая цена подписки |
| VIP | Длительность месячного / годового VIP | Сколько дней добавляет покупка |
| VIP | Скидка VIP на ГОСТ-токены, % | Скидка на токены для владельцев VIP |
| Лимиты объявлений | Лимит без VIP / с VIP | Сколько активных заказов и услуг суммарно можно держать |

Проверка значений при сохранении: проценты — от 0 до 100, количества (дни, штуки) —
целые положительные числа, цены — не отрицательные. Неподходящее значение не сохранится,
появится сообщение об ошибке.

Значения по умолчанию, которые заложены в коде на случай отсутствия настройки:
комиссия с вывода — 10%, реферальный бонус — 5%, максимум реферальных бонусов — 3,
минимальная сумма — 100 ₽, цена токена — 10 ₽, VIP — 300 ₽ за 30 дней и 1500 ₽ за 365 дней,
скидка VIP на токены — 20%, лимит объявлений — 2 без VIP и 10 с VIP. Актуальные
рабочие значения всегда видны прямо в этих полях — код подставляет свои цифры только
если настройки в базе нет.

Изменение любого параметра действует **только на будущие операции**. Уже проведённые
пополнения, выводы и покупки не пересчитываются.

**Категории форума** — список категорий с кнопками «Изменить» и «Удалить», кнопка
«Добавить» сверху. Поля категории: название (обязательно), описание, имя иконки
(из набора Lucide, например BookOpen) и порядок сортировки.

Осторожно с удалением: оно физическое, не мягкое, и спрашивает только «Удалить категорию?»
без предупреждения о темах внутри. Если в категории уже есть темы, удалять её не стоит.
Скрыть категорию, не удаляя, через интерфейс нельзя — в базе такая возможность есть,
но кнопки для неё не сделали.

## VIP-система

### Что VIP реально даёт

Ровно две работающие вещи:

1. **Больше объявлений.** Без VIP — 2 активных объявления, с VIP — 10. Лимит общий:
   заказы и услуги считаются вместе, любая комбинация в пределах числа. Оба числа
   настраиваются в разделе «Настройки».
2. **Скидка на ГОСТ-токены.** По умолчанию 20%, настраивается в «Настройках».
   Скидка даётся за наличие активной подписки.

Плюс косметика, которая уже сделана: золотой бейдж с короной рядом с ником,
ник с фиолетово-розовым градиентом и такое же свечение вокруг аватара — на профиле,
в карточках на бирже, в чате и на форуме. Больше никаких перков нет.

### Как покупается

С баланса кошелька, двумя вариантами: на 30 дней или на 365 дней (сроки и цены —
из «Настроек», по умолчанию 300 ₽ и 1500 ₽). Не автопродление: подписка просто
заканчивается.

Покупать можно сколько угодно раз подряд, в том числе пока текущая ещё активна —
дни **прибавляются** к остатку, а не перезаписывают его.

### Скидка на саму подписку по уровню — важный нюанс

У каждого пользователя есть уровень от 1 до 10, который растёт от репутации
(репутация начисляется за завершённые сделки). Уровень даёт скидку на покупку VIP:

- уровень 1 — полная цена;
- каждый следующий уровень — минус 10%;
- уровень 10 — VIP **бесплатно** (скидка 100%).

Это отдельная скидка, не та, что на токены. Она:

- **не настраивается через админку** — проценты зашиты в код;
- нигде в админке не отображается;
- считается на сервере в момент покупки, поэтому подделать цену со стороны
  пользователя нельзя.

Бесплатная активация на 10 уровне всё равно попадает в журнал транзакций (с суммой ноль).

### Что видит администратор

Практически ничего. Это самое слабое место VIP:

- в разделе «Пользователи» VIP-статуса нет;
- в «Журнале» покупки VIP видны, но без человекочитаемого названия, и их нельзя
  выбрать в фильтре типов;
- отдельного раздела «VIP» или «подписки» не существует;
- в «Финансах» доход от VIP не выделен отдельной строкой.

Проверить, есть ли у конкретного человека VIP, можно только посмотрев его публичный
профиль на сайте (там будет бейдж) или заглянув в базу данных.

### Что происходит, когда VIP заканчивается

Раз в час сервер сам проверяет истёкшие подписки. Если у человека объявлений больше,
чем позволяет базовый лимит, лишние **скрываются**, начиная с самых новых.
Ничего не удаляется:

- скрытые заказы и услуги видны владельцу в его личном кабинете и администратору,
  но не показываются на бирже;
- владелец сам решает, какие оставить видимыми в пределах лимита;
- отзывы и переписки по скрытым позициям остаются доступны участникам;
- но **писать в чат по скрытому из-за истечения VIP заказу нельзя** — история читается,
  поле ввода заблокировано с пояснением, что чат откроется после продления VIP.

Особенности этой проверки: первый раз она запускается через час после запуска сервера,
а не сразу, и повторяется каждый час — то есть если владелец без VIP снова включит
лишние объявления, в течение часа они опять скроются.

## Финансовая логика

### Пополнение — без комиссии

Подтверждённая сумма зачисляется на баланс один к одному. Платформа с пополнения
не берёт ничего.

Пополнение подтверждается вручную администратором: человек переводит деньги
по реквизитам из «Настроек», создаёт заявку и ждёт, пока вы её подтвердите.
Автоматического приёма платежей нет.

### Комиссия — только при выводе

Единственная точка, где платформа зарабатывает на движении денег.
Процент задаётся в «Настройках» («Комиссия с вывода»), в коде заложено 10%
на случай, если настройки нет. Актуальное значение всегда видно в этом поле
и подставляется в колонку «К выплате» в разделе «Выводы».

Как считается: при создании заявки с баланса списывается вся сумма. При подтверждении
пользователю переводится сумма минус процент, а разница остаётся платформе и попадает
в «Финансы» строкой «Комиссия с вывода средств».

Комиссия одинаковая для любых денег — заработанных на бирже и полученных как
реферальный бонус. Баланс не помнит, откуда пришли деньги.

При отклонении заявки на баланс возвращается **вся** сумма, без вычета комиссии.

### Реферальная программа

- Пригласивший получает процент (по умолчанию 5%) с **первых трёх** пополнений
  приглашённого. Процент, количество и минимальная сумма пополнения (по умолчанию 100 ₽) —
  всё в «Настройках».
- Бонус начисляется в момент, когда вы подтверждаете пополнение приглашённого,
  и сразу попадает на баланс пригласившего.
- Пополнение меньше минимальной суммы бонус не приносит и «слот» не расходует.
- Больше трёх бонусов выдать нельзя технически: слот выдаётся неделимой операцией
  с блокировкой строки, поэтому одновременные подтверждения не могут выдать лишний бонус.
- Про эти деньги комиссия не забыта — она возьмётся позже, когда пригласивший
  захочет их вывести.

### Как это выглядит в разделах

В «Финансах»: доход — комиссия с выводов и выручка от ГОСТ-токенов; реферальные выплаты
идут в минус; строка про комиссию реферальных пополнений всегда ноль (объяснение
выше, в описании раздела «Финансы»).

В «Журнале»: видны все движения — пополнения, выводы, оплаты и выплаты по заказам,
возвраты, залоги, реферальные бонусы. Покупки VIP и токенов там тоже есть, но без
нормального названия.

### ГОСТ-токены

Токены покупаются за рубли с баланса, цена — в «Настройках». Вся сумма считается
доходом платформы. **Обратной конвертации токенов в рубли нет** — вернуть деньги
за токены штатным способом невозможно, только правкой баланса в базе.

### Деньги по заказам

Для полноты картины, чтобы понимать споры:

- при взятии заказа стоимость резервируется у заказчика;
- при завершении исполнитель получает стоимость, залог (если был) возвращается заказчику;
- при отмене заказчику возвращается зарезервированное;
- если одна сторона подтвердила выполнение, а вторая молчит, через 24 часа заказ
  подтверждается автоматически и исполнителю выплачиваются деньги. Срок задаётся
  переменной на сервере, а не в админке.

Важная особенность автоподтверждения: оно срабатывает не по таймеру, а в момент,
когда кто-то открывает список заказов. Если на сайте затишье, заказ может простоять
дольше 24 часов и завершиться позже — когда кто-нибудь зайдёт.

## Частые вопросы

**«Пополнил, деньги не пришли»**

Пополнения подтверждаются вручную. Откройте «Пополнения» и найдите заявку.
Если она в статусе «Ожидает» — значит просто ещё не обработана: проверьте фактическое
поступление денег и подтвердите (или отклоните, если денег нет). Если заявка уже
«Подтверждено» — деньги на балансе, пусть человек обновит страницу кошелька.
Если денег так и нет при подтверждённой заявке — это сбой, ищите операцию в «Журнале».

**«Исполнитель пропал»**

Пока заказ в статусе «В работе» или «Ожидает подтверждения», любая сторона может
открыть спор — тогда решение за вами. Если исполнитель успел отметить работу
выполненной, а заказчик молчит, заказ автоматически завершится через 24 часа
(и наоборот). Если заказ висит и спор не открыт, вмешаться из админки нельзя —
объясните человеку через «Поддержку», что нужно открыть спор.

Помните про поломку раздела «Споры» (описана выше) — до её исправления
закрыть спор через админку не получится.

**«Вывод завис»**

Проверьте «Выводы». Заявка в статусе «Ожидает» — вы её ещё не выплатили: переведите
сумму из колонки «К выплате» и нажмите «Выплачено». Заявка «Выплачено» — система
считает, что деньги отправлены; проверяйте по банку, из системы больше ничего не сделать.
Если пользователь получил меньше, чем просил, — это комиссия с вывода, так и задумано,
процент виден в «Настройках».

Если человек жалуется, что не может **создать** заявку: сумма не может превышать
баланс, а созданная заявка сразу удерживает деньги — поэтому две заявки на одну и ту же
сумму создать нельзя. Ещё проверьте, не заблокирован ли аккаунт.

**«Жалоба на пользователя»**

Зависит от места:

- пост на форуме — пользователь жмёт «пожаловаться», жалоба приходит в «Форум» → «Жалобы»;
- переписка по заказу — открывается спор, он попадает в «Споры»;
- всё остальное — через «Поддержку», обращение появится у вас в разделе «Поддержка»;
- если человек в чате скидывает контакты или ведёт себя подозрительно, сообщение
  попадёт в «Модерацию» автоматически — но само оно не блокируется.

Наказание одно: бан в разделе «Пользователи» (или галочка бана при разрешении спора).
Частичных ограничений — мут, ограничение на форум и т.п. — в системе нет.

**«Забыл пароль»**

Всё работает само, вмешательство администратора не требуется: на странице входа есть
ссылка восстановления, человек вводит email, получает письмо и задаёт новый пароль.
Скажите пользователю проверить папку «Спам». Если письма нет совсем — проблема
в почтовых настройках, это к разработчику.

**«Хочу вернуть деньги за токены ГОСТ»**

Штатного способа нет. Только правка баланса в базе, вручную.

**«Расписание не работает»**

Скорее всего, истёк кеш. Идите в «Прогрев расписания» и запустите прогрев.
Кеш живёт 30 часов, поэтому это нужно делать примерно раз в сутки.

## Важные правила

1. **Не подтверждайте пополнение, пока не увидели деньги.** Зачисление необратимо,
   штатной кнопки отката нет.

2. **Сначала переведите деньги, потом жмите «Выплачено».** Кнопка ничего не переводит,
   она только фиксирует факт. Переводить нужно сумму из колонки «К выплате», а не
   полную сумму заявки.

3. **Спор решается один раз.** Система физически не даст выплатить дважды, но и передумать
   после нажатия нельзя. Сначала читайте переписку по заказу, потом нажимайте.

4. **Помните, что при решении в пользу исполнителя залог тоже уходит исполнителю.**

5. **Баланс пользователей — не ваша прибыль.** В «Финансах» он показан отдельной карточкой
   именно поэтому. Эту сумму нужно держать доступной для выплат.

6. **Отклонение заявки на вывод возвращает деньги автоматически.** Не надо возвращать
   их вручную ещё раз — получится двойной возврат.

7. **Права последнего администратора снять нельзя** — система заблокирует действие.
   Но вы можете снять права у себя, если есть второй админ, и потерять доступ.

8. **Изменение настроек действует только вперёд.** Уже проведённые операции
   не пересчитываются.

9. **Бан не прерывает активные сделки.** Если нужно остановить конкретный заказ,
   это делается только через спор.

10. **Прогревайте расписание примерно раз в сутки**, иначе раздел «Расписание»
    у пользователей перестанет работать.

11. **Не удаляйте категории форума, в которых есть темы.**

12. **Не правьте деньги напрямую в базе, если можно обойтись админкой.** Балансы
    меняются через специальные неделимые операции; ручная правка их не учтёт,
    и «Финансы» с «Журналом» разойдутся с реальностью.

## В планах и известные ограничения

Список собран из пометок в коде, документа с техзаданием и прямой проверки страниц админки.

### Крупные незакрытые задачи

**Полная переделка системы оплаты.** Текущая схема — временная: пользователь переводит
деньги по реквизитам, создаёт заявку, администратор вручную сверяет поступление
и подтверждает; вывод так же вручную через банк. Планируется перевод пополнений
и выводов на специализированную платёжную платформу с автоматическим подтверждением.
До этого пополнения и выводы остаются ручной ежедневной работой администратора.

**Тестирование и доработка ГОСТ-калькулятора.** Раздел сознательно закрыт для всех,
кроме администраторов, — он ещё не готов к публичному использованию. Нужно проверить
качество генерации на реальных заданиях и доработать. Дополнительно: через админку
нельзя добавлять новые шаги, разделы, таблицы и исходные параметры в шаблоны —
только править существующие.

### Поломки, которые стоит починить в первую очередь

- **Раздел «Споры» не открывается при наличии открытого спора** — интерфейс ждёт
  от сервера поля, которых сервер не присылает. Это блокирует всю работу со спорами.
- **Список «Чаты» без подписей** — по той же причине: почти все строки выглядят как
  «Без названия» и «Участники не найдены».
- **Плитка «Активных заказов» на дашборде ведёт на пользователей**, а не на заказы.
- **Плитка «Тикетов поддержки» на дашборде не кликается.**
- **Метка «РЕФ.» в «Пополнениях» считает предел бонусов равным трём независимо
  от настроек.**
- **Значок «5%» в «Финансах» — статичная надпись,** не связанная с настройкой
  реферального процента.

### Чего в админке нет, хотя логично было бы

- VIP-статус нигде не отображается: ни в пользователях, ни в журнале, ни в финансах.
- Нет комментария при отклонении заявки на пополнение и на вывод, хотя пользователю
  такой комментарий показывается.
- Нет возможности скрыть категорию форума без удаления.
- Нет страниц в списке пользователей — он грузится целиком.
- Нет аватарок в списке пользователей и не выводятся рейтинги, хотя данные есть.
- В журнале нет фильтров и названий для покупок VIP, покупок токенов
  и реферальных пополнений; реферальное пополнение показывается как расход.
- В журнале жёсткий предел 500 записей, и фильтр по нику применяется уже после него.
- Статистика дашборда считается по последним 2000 заказам.
- Нет выгрузки отчётов в таблицу или PDF.
- Нет двухфакторной аутентификации — только email и пароль.
- Нет автоматического расписания прогрева, нет продолжения прогрева с места остановки,
  и нельзя вывести прогрев из зависшего состояния «выполняется».
- Нет уведомлений в Telegram по флагам в личных чатах и по новым обращениям
  в поддержку (уведомления есть по заявкам на пополнение и вывод, по подтверждению
  пополнения, по реферальному бонусу, по новому спору, по решению спора
  и по флагам на форуме).

### Известные технические компромиссы

- **Начисление репутации не является неделимой операцией.** При двух одновременных
  начислениях часть очков может потеряться. Для репутации это признано допустимым;
  для денег такой подход нигде не используется.
- **Сортировка лент (VIP выше остальных) применяется после ограничения выборки.**
  Пока объявлений мало — незаметно. Когда их станет больше лимита выборки,
  VIP со старым объявлением может не попасть в начало ленты.
- **Достижение «10+ расчётов ГОСТ» считается по покупкам токенов**, а не по фактическим
  расчётам: ГОСТ-сервис не сообщает платформе о каждой генерации.
- **Достижение «первые дни платформы» считается от даты создания самого первого
  аккаунта**, а не от реальной даты запуска, — точной даты запуска в настройках нет.
- **Скидка VIP по уровню живёт только в коде сервера** и не выведена в настройки.
- **Скрытие лишних объявлений при истечении VIP реализовано по-разному** для заказов
  и услуг (у услуг это переключатель активности, у заказов — отдельный признак
  скрытия), поэтому поведение может слегка отличаться.
- **Автотестов нет.** Есть один сквозной проверочный скрипт, который прогоняется целиком
  и не даёт запустить отдельный шаг. После добавления скидки VIP он не прогонялся.
  Любое изменение денежной логики стоит проверять руками на тестовом аккаунте.
- **Файлы миграций базы в репозитории не отражают то, что реально применено**
  на рабочем проекте. Это отдельная разобранная история, подробности — в отчётах
  об аудите в папке документации. Практический вывод для администратора один:
  не просите «просто накатить миграции» — там есть файлы, которые сломают рабочую базу.
